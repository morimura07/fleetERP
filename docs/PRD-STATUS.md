# PRD Module Status — Transport & Logistics ERP

>
> **Architecture note:** the app is split into two independently-deployable services — `frontend/` (Next.js web) and `backend/` (standalone Hono API that owns all DB access). The API is Hono route handlers (not Next.js Route Handlers). Several cross-cutting tables are **duplicated** and must be kept in sync: RBAC (`backend/src/lib/rbac.ts` authoritative, `frontend/lib/rbac.ts` mirror), Zod validations (`backend/src/lib/validations.ts` ↔ `frontend/lib/validations.ts`), and enum/label maps (`frontend/lib/enums.ts`, `frontend/lib/labels.ts`).
>
> **Multi-company (2026-07):** single-DB multi-tenancy is live. A `Company` registry defines each legal entity; a `dataAreaId` string column partitions every business record and is **enforced at the query layer** (`backend/src/lib/scope.ts` — `areaScope`/`areaForWrite`/`assertSameArea`). ADMINs get a cross-entity view with a company switcher (`X-Data-Area` header).

| Driver & Safety | Active Drivers, Driver Turnover, Total Drivers | ✅ |

**Internal capture models (Tier C, 2026-07):** `DockEvent` (arrival/departure → turnaround), `DamageReport` (`DMG-` sequence, status lifecycle → damage/claim rate), `CustomerFeedback` (CSAT 1–5 / NPS 0–10). Each has its own admin screen under Operations and is gated by the `kpi:read`/`kpi:write` permissions. **External-feed KPIs (real telematics idle time, e-invoicing accuracy, credit scoring) remain integration-gated (PRD §5).**
